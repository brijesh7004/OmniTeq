Platform

Everything you need to scale

A complete suite of tools to manage your IoT infrastructure from prototype to production.

Real-Time Telemetry

Batch up to 500 readings per ingest call and stream them to your dashboard over WebSockets. Float, integer, boolean and string variables are all first class.

Acknowledged Commands

Dispatch typed, validated parameters to any device and follow the full lifecycle — queued, sent, executed, success or failed — with a TTL so stale commands expire safely.

Secure Provisioning

Every device gets a secret key issued once at creation and stored only as a hash. Users authenticate separately with short-lived JWTs and rotating refresh tokens.

Project Hierarchy

Organise your fleet as Project → Device → Sensor → Variable, so thousands of readings stay queryable, attributable and scoped to the right team.

Time-Series Aggregation

TimescaleDB time_bucket() returns min, max, avg and count across seven intervals from one minute to one day — fast, even over months of history.

Rules & Alerts

Define thresholds on any variable and let the rule engine watch them around the clock. Alert history is grouped per project so nothing gets lost in a flat list.

Outbound Webhooks

Forward telemetry, command results, rule triggers and device events straight into your own systems — ERP, MES, Slack or a custom endpoint.

Cloud Studio

Model controllers, sensors, variables, actuators and rules visually, generate matching firmware, then export the whole project as JSON for backup or review.

How it works

From bare board to live fleet

Three steps, one afternoon. No brokers to run, no time-series database to operate.

01

Provision

Create a project and register a device. The platform returns a device_id and a one-time secret_key — the only credentials your firmware needs.

02

Connect

Flash the reference firmware for your board, or POST to /ingest/telemetry from anything that speaks HTTPS. Heartbeats report firmware version and IP.

03

Control

Chart live values, set rules, and dispatch commands back down. Devices poll for pending work and acknowledge every execution with success or failure.

FAQ

Questions, answered

How does a device authenticate?

Devices never hold a user token. On creation each device receives a device_id and a secret_key that is shown exactly once and stored server-side only as a hash. Firmware sends that pair with every ingest, command-poll and heartbeat call. People and dashboards authenticate separately with a JWT access token plus a rotating refresh token.

Which protocols and boards are supported?

Ingest, command polling and acknowledgements run over HTTPS REST; the dashboard receives live updates over WebSockets. Ready-to-flash reference firmware is included for ESP32, ESP32-S3, ESP8266 and Arduino Nano 33 IoT — but any device, gateway or script that can make an HTTPS request will work.

How is historical telemetry stored and queried?

Readings land in a TimescaleDB hypertable. Raw range queries return up to 5,000 rows per call, and aggregate queries use time_bucket() to return min, max, avg and count at 1m, 5m, 15m, 30m, 1h, 6h or 1d resolution. Only numeric variables can be aggregated; string variables are returned raw.

How do commands actually reach a device?

You dispatch against a command template, and the API validates that every required parameter is present and correctly typed before returning 202 Accepted. The command is queued; the device picks it up by polling /ingest/commands/pending, then acknowledges with success or failed. Anything not collected within its TTL — one hour by default — expires instead of firing late.

Can I export my configuration and data?

Yes. Cloud Studio exports a complete project — controller, sensors, variables, actuators, commands and rules — as JSON, and imports the same schema back. Telemetry export to CSV is available from the Basic tier, and JSON export from Moderate upward.

What happens when I hit a plan limit?

The gateway returns an explicit PLAN_LIMIT_EXCEEDED error rather than silently dropping readings, so your firmware can retry or back off deliberately. You can review live quota usage at any time under Settings, and change tier without re-provisioning devices.
