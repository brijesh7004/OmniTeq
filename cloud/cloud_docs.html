Developer Documentation

Connect OmniTeq Cloud to ESP32, ESP32-S3, ESP8266 and Arduino Nano 33 IoT boards: provision credentials, flash production firmware, and stream telemetry into the live dashboards.

Gateway -
Firmware library OmniteqIoTCloud 1.0.0
Transport HTTPS / REST
Hardware Integration Suite. A real-time, low-latency ingest gateway that connects remote microcontrollers to the cloud console. Boards publish sensor values as standard REST packets and receive active remote commands over simple HTTP polling loops.
Connecting ESP32 / ESP32-S3 / ESP8266 / Nano 33 IoT
Step 1 - Establish internet handshake
Connect your board to the local 2.4 GHz Wi-Fi access point using its built-in network adapter.
Step 2 - Obtain device secret keys
Deploy a device under a project to generate a specific Device ID and access Secret Key.
Step 3 - Deploy production firmware
Compile and flash the production C++ template to stream metrics and poll commands instantly.
Step 1: Device Credentials
To authorize physical boards with the OmniTeq Cloud, provide both credential parameters in every ingest payload.
FieldDescription
device_idThe device UUID returned when the device was created (e.g. 123e4567-e89b-12d3-a456-426614174000).
secret_keyThe secret returned only once, in the device-creation response (e.g. sk_live_6c085b3b19424c88a8f15efdf281e05a).
Keep secrets private. Never check raw secret keys into public source repositories - treat them as private system credentials.
Step 2: C++ Arduino Code

Select your board to view a production-ready Arduino sketch that connects to Wi-Fi, sends batched telemetry, polls for cloud commands and acknowledges them. It uses the OmniteqIoTCloud library, which handles HTTP, JSON and the ingest/command endpoints for you.

Library required: install OmniteqIoTCloud from OmniteqIoTCloud-1.0.0.zip via Arduino IDE → Sketch → Include Library → Add .ZIP Library... before compiling. Pick the board below: ESP32 / ESP32-S3 (WiFi.h + WiFiClientSecure), ESP8266 (ESP8266WiFi + BearSSL) or Arduino Nano 33 IoT (SPI + WiFiNINA + WiFiSSLClient). Every sketch connects over HTTPS - for testing client.setInsecure() is used; in production replace it with your CA certificate. Fill in every YOUR_* value, including the three variable UUIDs from the Sensors page.

Step 3: Ingest Protocol Specs
Devices talk to the gateway at over HTTPS. The library wraps these calls, but every request still carries device_id and secret_key in the JSON payload.
POST
/ingest/telemetry
Transmit sensor data. Variable IDs must align with the variables mapped on the sending device. Up to 500 readings per call; each stored reading is also pushed to open live dashboards.
Device key
▼
Request body
Response
Errors
FieldTypeRequiredDescription

readings[].variable_idstringrequiredUUID of the target variable on this device
readings[].valuenumber | string | booleanrequiredMust match the variable's data_type
readings[].recorded_atstringoptionalISO 8601 UTC. Defaults to server receive time

Outbound Webhooks
Push device and command events to an HTTPS endpoint of your choice. Webhooks require a plan with webhooks_enabled and a signing secret, which is returned once when the webhook is created.
Verified contract. The request body accepts only the three fields below. Any additional field, and any event value outside the enum, is rejected with 400. Webhooks are not part of API Quick Reference v2.0 - the contract was verified against the live gateway.
POST
/webhooks
Register an outbound webhook and receive its signing secret.
Auth required
▼
Request body
Response
FieldTypeRequiredDescription
urlstringrequiredHTTPS endpoint that will receive deliveries
event_typesarrayrequiredOne or more values from the event enum below. This is the only accepted key name
enabledbooleanrequiredWhether deliveries are active

Example
{
  "url": "https://api.yourdomain.com/webhooks",
  "event_types": ["device.online", "command.success"],
  "enabled": true
}

Allowed event_types (strict enum)
ValueFires when
device.onlineA device reports in after being offline
device.offlineA device stops reporting
command.successA dispatched command is acknowledged as executed
command.failedA dispatched command is acknowledged as failed
201 Created - the secret is returned once and never shown again

  "success": true,
  "data": {
    "id": "7c9bc7b1-aa08-40a1-8178-30a6a08b3394",

    "event_types": ["device.online", "command.success"],
    "enabled": true,
    "created_at": "2026-09-26T16:20:18.472Z",
    "secret": "fbde143c23b8e001d2a9ef0f1fb90ed4a2ab60d514700fe0"

}
