Fixed in v3.0 (database migration 004)

  • Deleting a device or project whose devices have received commands now works. It used to return 500; the command history is now deleted along with it.
  • Replacing a command’s parameters after it has been sent now works. It used to return 500. Parameters are matched by name, so commands already sent or queued keep their values.
  • Easy to miss (unchanged behavior): a batch with some rejected readings returns 200 with success: false (207 only when all are rejected), and command values reach the device as strings ("false", "28.5").
