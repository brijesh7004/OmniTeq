  ------------------------------------------------------------------

  1. JSON error envelope (see section 0b and section 14)
     PowerShell 5.1 drops non-2xx bodies on this platform; curl.exe
     recovered 38 of them, so the gateway DOES send a payload.
     Any error.code still missing below is then a genuine omission.
     Fix: return { success:false, error:{ code, message } } as per the
     standard error codes table in API Quick Reference v2.0 section 10.

  2. DELETE cascade is incomplete (HIGH)
     DELETE /devices/:id and /projects/:id return 500 when a dispatched
     command exists: cmd_instance_params rows are not removed before
     cmd_parameters, violating cmd_instance_params_parameter_id_fkey.
     Fix: delete cmd_instance_params (and cmd_instances) first.
     The console works around it via devices/projects.deleteCascade().

  3. Command required-parameters are not enforced (MEDIUM)
     POST /command-templates/:id/dispatch substitutes an empty string for a
     missing required parameter and returns 202 instead of 400
     MISSING_REQUIRED_PARAM (see section 7). The console validates
     client-side, so an API-only client can still dispatch an empty value.

  4. Webhooks are undocumented (LOW)
     POST /webhooks works but has no section in the API reference. The
     verified contract is asserted in section 11; mirror it into the docs.

  5. Duplicate variable label on an untouched enum (LOW)
     data_type only accepts float/integer/boolean/string; 'numeric' is a
     400. The console only offers the valid four.
