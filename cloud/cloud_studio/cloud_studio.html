SEC 04

Output Actuators & Command Templates

Define power switches, relays, motors, buzzers, and local displays, then map each one to an OmniTeq Cloud command template.

Quick Add:
☁
Actuators vs. Command Templates: an actuator is a physical output on a GPIO; a command template is the cloud-side definition a dashboard button or rule dispatches. Commands arrive through GET /ingest/commands/pending as a template id plus a parameters JSON string and must be answered with POST /ingest/commands/:instanceId/ack. Bind each actuator to a template below so the generated processCommand() can dispatch it.

Cloud Command Templates

Exactly the schema used by Cloud → Commands → Add Template: a name, a description and an ordered parameter list.

Each parameter mirrors param_name / param_type / param_order / is_required / default_value.

Firmware Deployment & Cloud Link Ready

Your OmniteqIoTCloud sketch is generated and ready for flashing with the Arduino IDE or Arduino CLI.

1
Install the Library
Arduino IDE → Sketch → Include Library → Add .ZIP Library… and select OmniteqIoTCloud-1.0.0.zip (the sketch starts with #include <OmniteqIoTCloud.h>). The board's own Wi-Fi stack is built in: WiFi/WiFiClientSecure for ESP32 & ESP32-S3, ESP8266WiFi for ESP8266, or WiFiNINA for the Nano 33 IoT.
2
Paste Credentials
Replace YOUR_WIFI_SSID, YOUR_DEVICE_ID, YOUR_SECRET_KEY and every YOUR_*_VARIABLE_UUID placeholder, or regenerate after filling Section 01.
3
Flash & Watch Telemetry
Upload, open Serial at 115200 baud, then confirm the boot heartbeat plus batch telemetry in Cloud → Telemetry.
